# つづき / Tsuzuki

Android向けの日本語小説リーダーと読み上げアプリです。

Tsuzuki is an Android reader for Japanese long-form text. It preserves ruby readings and speaker assignments, and can synthesize speech locally with VOICEVOX once its voice data is installed. To try the reader with your own text, import a TXT file. See the [build guide](../scripts/BUILD.md) and [validation notes](../VALIDATION.md).

カクヨム・小説家になろう・Wuxiaworldを一つの本棚・読書画面で扱う個人用アプリです。本文、読書位置、既読状態、付箋を作品ごとに保存します。1.9.0では **作品メモ＋一話全文を基本にしたGPT解析**、**音声の部分生成からの再生**、**最大3区間の先読み**を追加しました。音声は引き続きVOICEVOXで端末内生成します。

## 1.12.2 — 目次の検索と読書位置

目次の「絞る」から、話数や見出しで絞り込めます。話数の入力は全角数字にも対応します。目次の更新が届いても入力欄を保持します。「現在の話へ」を押すと、読書位置の行まで移動します。絞り込みでその行が隠れている場合は、先に絞り込みを解除します。

## 1.12.1 — 読書中のスクロール位置

本文を上下にスワイプすると操作バーが本文の上で切り替わります。表示領域の大きさと本文の基準位置をそろえ、指を離したあとの慣性スクロール中も表示位置を保ちます。連続する話の読み込みでは、画面から遠く離れた話を整理する処理を、スクロールが落ち着いてから実行します。

## 1.12.0 — 自然な会話

「読み上げ・AI設定」→「台詞の演技」で「自然な会話」「アニメ調」「標準朗読」を選べます。新規利用時と、1.11.0でアニメ調を使っていた場合の既定は「自然な会話」です。「標準朗読」を選んでいた場合はその設定を引き継ぎます。

自然な会話では、普段のやりとりを同じ声色で続け、意味のある語だけに抑揚を付けられます。自動解析の速さ・音高・音量の変化を控えめにし、驚きのあとの間や呼び止める声の強さを抑えます。声の配役、手動で固定した間、単語指定は保存済みのものを使います。地の文は従来の読み方です。

設定の「試聴する台詞」で日常会話と呼び止める台詞を選び、同じ声で3通りを試せます。音声データが準備済みなら、新しい取得やGPTの再解析は不要です。

## 1.11.0 — 台詞のアニメ調と聴き比べ

「オフラインのキャラ音声」では、台詞と心の声に「アニメ調」を標準で使います。呼び止めるときは声を張って短く発音し、頼み込むときは語尾を伸ばして声を落とします。場面の演技、単語の演技、話者ごとに収録された声色を組み合わせます。地の文には従来の読み方を使います。

「読み上げ・AI設定」→「キャラ音声 · VOICEVOX」→「台詞の演技」で切り替えられます。音声データが準備済みなら、同じキャラの「えっ……待って！お願い、行かないで。」を「標準を試聴」と「アニメ調を試聴」で比較できます。試聴だけなら保存操作やGPT通信は不要です。通常の朗読にも使うモードを変えたときは設定を保存してください。

保存済みの配役・演技・読み・単語指定はそのまま使えます。解析していない台詞は、句読点や短い反応の表記から読み方を選びます。

## 1.10.0 — 単語の演技

「オフラインのキャラ音声」で、目立たせたい単語の高さと母音の長さを音声へ反映します。強調、やわらかく、ためらい、言い切りの4種類を3段階で扱います。1語ごとのAPI呼び出し・音声の分割は行いません。GPTは文脈で必要な語を選び、それ以外は声の通常のアクセントで読みます。本文から得た発音が保存済みの読みと一致するときは、元表記のアクセントを使います。

更新前に読みまで解析した話では「読み上げ」→「単語の演技を追加解析」を押してください。「区間を修正」から読みの画面を開き、「単語の演技」を展開すると、任意の語の追加・削除、表現・強さ・出現回数の手動指定ができます。ここでの演技指定にGPT通信は使いません。手動固定した読みの区間は自動追加の対象外です。端末標準のTTSは引き続き読みを利用します。

## 1.9.2 — 漢字・助詞の読み

新しく開始するGPT解析に、漢字・人名・文脈で読みが変わる語・助詞の音声用の読みを加えました。通常の一話では、配役・感情・抑揚と同じ一回の応答に読みを含めます。句ごとに追加の通信を行う方式ではありません。非常に長い話や出力上限に当たる場合は、従来と同じく章内の対象を分けて続けます。

- 「母は花を運ぶ」では、語中の「ハ」と助詞の「ワ」を区別します。助詞の「へ」は「エ」、「を」は「オ」を指定します。
- 「生物」は文脈に応じて「セーブツ／ナマモノ」などを判断し、「今日」は音声用に「キョー」と指定します。一般の辞書表記と音としての表記は異なる場合があります。
- 本文に作者のルビがある場合は、その表記を優先します。「ルビを使う」がオフのときは本文から解析します。
- 読みは元本文とは別に保存します。本文、付箋、既存の区間境界、演技データを読みの文字数に合わせて書き換えません。
- 読みを指定した後は端末内のVOICEVOXと端末TTSで利用します。音声データと本文・解析結果が保存済みなら、新しいGPT通信なしで再生できます。

### すでに解析済みの話へ追加する

「読み上げ」で **「漢字・助詞の読みを追加解析」** を押します。同じ本文・同じ解析モデルの既存配役や演技は保持して、足りない読みを追加します。新しい話では通常のGPT解析に含まれます。読みが揃っている話を再確認しても、読みのためだけの再要求は行いません。

更新前に中断した範囲は、開始時の方式で再開します。古い範囲の続きを再開しただけで、読みの追加要求は発生しません。読みを追加したい話は、新しく一話または範囲解析を開始してください。

### 読みを手動で直す

「区間を修正」から対象の区間を開き、漢字・助詞の読みの画面へ進みます。元の本文、ルビを反映した元表記、音声用の読みを比べ、句ごとに修正できます。

**読みだけを固定して保存**すると、その読みを再解析でも優先します。話者・声・抑揚の固定とは独立しており、読みの修正だけで配役や演技を固定・解除しません。手動で作者のルビとは異なる音に修正することもできます。

音として読ませたい表記を、ひらがなまたはカタカナで入力します。例は「ハハワハナオハコブ」。元表記と同一の句や漢字が残る句は、音声エンジンの通常の読みで処理します。明示したかな読みは音声入力時にカタカナ化し、助詞としての再解釈を抑えます。空白だけの句は無音のままです。

固定を解除すると、その区間の読みを削除し、次の明示的な解析で付け直せます。解除するだけではGPTへ送信しません。応答待ちの間に読みを固定した場合は手動の読みを保持し、解除によって未準備になった場合は古い返答を採用せず、解析を中断して理由を表示します。保存した範囲から再開してください。

読みを修正すると再生を停止し、次の再生では修正後の読みから音声を生成します。読みが変わった区間には以前の音声キャッシュを使いません。本文と演技が同じままでも読みの変更を区別します。

日本語の読みの意味的な正しさにはGPTの判断が含まれます。構造・対象句・ルビの対応は検証しますが、正答率の実測ではありません。自作例の指定読みがVOICEVOXの実際の音素・音声へ届くことと、旧データ・手動変更の保持を検証しています。詳細は `VALIDATION.md` を参照してください。

## 1.9.1の修正と処理状況の表示

配役で同じ人物の別名を統合したとき、作品メモの人物IDへ統合結果が反映されず、正しい根拠を持つメモも拒否される不具合を修正しました。通常の一話解析と過去メモの準備の両方が対象です。未知の人物・確認できない根拠は引き続き拒否し、推測で埋めません。保存済みのメモ・手動修正・配役は維持します。

エラーで停止した範囲は、更新後に「保存した範囲の続きを解析」から再開できます。本文・メモ・アプリデータを削除する必要はありません。

解析欄と通知に、本文取得・入力準備・接続情報確認・GPTへ送信／応答待ち・応答検証・保存を表示します。対象話数、確定した完了数、記録済みの要求回数、今回の実行と現在工程の経過時間を確認できます。GPT内部の進捗率は取得できないため表示せず、応答待ちでは時計を更新します。経過時間は端末の時計で計測し、開始・再開からの時間です。

メモの拒否理由は人物参照・根拠参照・項目形式などに分類します。「エラーの詳細」で識別情報を確認・コピーできます。本文、メモ本文、人物名、出典URL、ログイン情報は診断へ含めません。

## インストール・更新

1. **Android 8.0以上、64bitのarm64またはx86_64端末**で `tsuzuki-1.12.1-personal.apk` を開きます。32bit専用端末には対応しません。
2. Androidに確認された場合は、APKを開いたアプリについて「この提供元のアプリを許可」を有効にします。
3. 既に「つづき」を利用している場合は、そのまま上書きインストールします。

従来版と同じパッケージ名・署名鍵を使用しています。アンインストールは不要です。本棚、保存本文、付箋、サイトのログインCookie、解析済み区間、人物情報、読書・読み上げ位置を引き継ぎます。DBスキーマは変更していません。アンインストールすると端末内のアプリデータは削除されます。別の保存先に書き出したTXTは残ります。

## 読み上げの構成

| 処理 | 担当 | 通信が必要な場面 |
| --- | --- | --- |
| 話者・感情・抑揚の新規解析 | ChatGPTアカウントのGPT、または明示的に選んだOpenAI API | 解析を開始・再開するとき |
| キャラ音声の生成 | VOICEVOX CORE 0.17.1 + VOICEVOX ONNX Runtime 1.23.2 | 初回の音声モデル・辞書取得 |
| 保存済みの本文・解析結果からの再生 | 端末内のVOICEVOX | 初回準備後は不要 |
| 端末の音声 | Android TTS | 選んだ音声エンジンによる。通信不要の音声を選択可能 |

Geminiのキー設定、音声モデル選択、本文送信処理を削除しました。キャラ音声の生成には音声APIキーを使用しません。音声がキャッシュにない文章も、音声モデルと本文が端末にあれば新しく生成できます。未解析の文章も標準の読み方で再生できますが、人物ごとの配役やGPTが判断した抑揚を使うには、その部分の解析結果を事前に保存してください。

この版はVOICEVOXを採用し、Style-Bert-VITS2は同梱していません。キャラ音声は日本語を中心に使用します。Wuxiaworldなどの英語本文には、音声方式を「端末の音声」にして英語のTTS音声を選べます。本文の翻訳機能はありません。

### 最初の音声設定

1. 「設定」→ **「音声・AI・ChatGPTログイン」** を開きます。「読み上げ・AI設定」が表示されます。
2. **「オフラインのキャラ音声」** を選びます。新規利用時の既定値です。
3. 「キャラ音声 · VOICEVOX」で **「音声データをダウンロード」** を押します。設定画面を開くだけではダウンロードしません。
4. 進捗を確認します。必要なら「ダウンロードを中断」を押し、後から「ダウンロードを続ける」で再開できます。失敗時は「ダウンロードを再試行」を使います。
5. **「オフラインで読み上げできます」** と表示されたら、**「10種類の声を聴き比べる」** を開き、「試聴」で確認します。
6. 「新しい配役の既定音声」を選び、「設定を保存」を押します。既に登録済みの人物の声は変更されません。

試聴だけでは作品の配役と読み上げ位置を変更しません。試聴の停止ボタンは音声設定と配役画面にあり、通常の読書コントローラーを非表示にしていても操作できます。「音声クレジット・利用条件」から各音声・辞書・ソフトウェアの情報をアプリ内で読めます。

### 容量とオフライン利用

| 項目 | 容量・扱い |
| --- | --- |
| 初回ダウンロード | 音声モデルと辞書の合計 **565,360,558 bytes（約565 MB）** |
| 準備後の音声データ | **649,018,528 bytes（約649 MB）** |
| 初回に確保する空き容量の目安 | **約800 MB以上**。取得・確認・展開用の領域を含む |
| 生成済み音声のキャッシュ | 別途、最大 **256 MiB** を目安に古い音声から整理 |
| 保存した小説本文 | 上記とは別に、保存した作品の分だけ使用 |

MBは10進表記、MiBは1,048,576 bytes単位です。音声モデルと辞書はAPKへ埋め込まず、初回操作で別途取得します。APKに入っている実行ライブラリとは別の容量です。画面の取得量・使用容量・空き容量の目安は音声データ管理側の状態から表示します。

初回準備後は、**音声データ・読みたい本文・使いたい解析結果**を端末に保存しておけばオフラインで聴けます。GPTの新規解析と未保存の話の取得には通信が必要です。「生成済み音声のキャッシュを削除」を使っても音声モデルと配役は残り、次の再生時に端末で音声を作り直します。音声ファイルの全編一括出力はありません。

### 旧版からの配役移行

保存済みの人物ID、名前、別名、役割、話し方、手動固定状態、解析済み区間、位置情報を保持します。以前のGeminiの声とVOICEVOXの声は異なるため、VOICEVOXの割り当てがない人物には、移行時に一度だけ声を割り当てます。以前と同じ声色の再現ではありません。

移行後は割り当てを保存し、再解析・新章・感情・GPTモデル・既定音声の変更で自動的に入れ替えません。作品ごとの「配役・声」ページで利用者が変更できます。旧Geminiの認証キーと関連設定は移行時に削除し、旧音声キャッシュはVOICEVOX用として再生しません。OpenAIの解析用設定とChatGPTの登録は引き継ぎます。

## GPTで話者・抑揚を解析する

1. 「読み上げ・AI設定」の「GPT · 解析用」で **Continue with ChatGPT** を押します。
2. 端末のブラウザーに表示されるOpenAIの画面でログインし、このアプリでのプラン利用を許可します。
3. アプリに戻り、初回案内を確認します。取得されたモデル一覧から使用するモデルを選び、「設定を保存」を押します。
4. 章を開いて「聴く」→ **「この話をGPT解析」** を押します。本文送信を確認して開始します。
5. 解析後、「配役・声を編集」や「区間を修正」で確認・修正してから再生します。

ChatGPTアカウント方式ではOpenAI APIキーは不要です。利用できるモデル・利用枠はアカウントの権限に従います。「利用量を管理」から確認できます。上限や認証エラーでは解析を止め、完了済みの結果を保持します。別モデルやAPIキー方式への自動切り替えはありません。

「APIキー方式を使う場合」には従来のOpenAI API方式も残しています。明示的に選んで保存した場合だけ使い、ChatGPTプランとは別の利用枠・料金になります。ログイン・モデル選択・音声設定だけでは本文解析を開始しません。

### 一話全体から細かい演技を決める（1.9.0）

設定の「精密な演技解析」と「作品メモ」は既定でオンです。通常の一話は、固定配役・過去の作品メモ・一話全文をまとめてGPTへ渡し、1回の応答で話者と演技を決定します。GPTへの要求単位と、演技・合成の細かさは分離しています。句ごとの感情や間の指定は残ります。更新・起動・設定画面の表示だけでは解析しません。既に有効な詳細演技がある区間と手動固定した区間は再利用します。

| 指定 | 精密解析の扱い |
| --- | --- |
| 解析の文脈 | 通常は一話全文と固定配役、過去の作品メモ。長大な話だけ段階的に処理 |
| 演技の単位 | 区間の内側の句読点・文末・三点リーダーなど。本文と読み位置の区間IDは変更しない |
| 感情 | 自然、喜び、悲しみ、怒り、不安、驚き、落ち着き、緊張、安堵、決意、照れ、皮肉の12分類 |
| 発声 | 自然、やわらかく、ささやく、はっきり、切迫、ためらうの6分類 |
| 数値 | 強さ、速さ、高さ、抑揚、音量、句の強調。人物の声・基本話速・基本高さを維持 |
| 間 | 各部分の後に0〜1,200 ms。句読点の間との二重加算を避ける |
| 語尾 | 自動、上げる、下げる、保つ、短く切る。声の有声部の語尾を限定的に調整 |
| 応答 | 共通の演技指定と変化した箇所のIDを返し、アプリ内で元の全演技部分へ展開 |
| 検証 | 全ID、欠落・重複、数値範囲、本文hash、作品メモの出典をアプリで確認 |

新規の精密解析では、1.8.0の必須だった「演技案→GPT再確認」の2回処理を行いません。構造検証を通過した完全な応答だけを保存します。「GPT解析済み」と表示し、旧版の2段階結果の「GPT再確認済み」と区別します。途中の不完全な応答は採用しません。

1要求の対象は最大320区間・1,200演技部分・48,000文字を目安にします。64,000文字までの話では分割時も一話全文を文脈として渡し、それを超える話では対象部分と周辺の文脈を使います。長大な話は残りを順番に処理し、章末を切り捨てません。モデルが出力上限を明示した場合だけ対象を減らして再試行します。過去メモの初回準備は別の処理です。241区間の同じ合成試験では、GPT要求数が従来62回から1回へ減りました。これは要求回数の比較であり、実モデルの所要時間や62倍の速度向上を示す値ではありません。

GPTには演技部分のIDと本文を渡し、返答はIDと演技メタデータに限定します。境界と本文hashはアプリが決め、全ての文字を順序どおり扱います。モデルが返した文章で本文を置換したり、息・笑い声・台詞を追加したりしません。

**この細かさは、感情判定の正答率や声優同等の品質を示しません。** 実小説に対する話者・感情の正答率と、聴取者による演技品質は未測定です。皮肉、意図的な嘘、省略された話者、複雑な内心は誤ることがあります。構造検証も意味の正しさを証明しません。画面の確信度はモデルの自己評価で、実測精度ではありません。

VOICEVOXの対応スタイルと音声パラメーターで表現できる範囲に限られます。感情名を指定しても、その声が持たない泣き声・笑い声・叫びや、特定の声優の演技を再現する機能にはなりません。句の強調と語尾の限定調整に対応しますが、全単語・全モーラへGPTが個別の演技を付ける方式ではありません。標準の端末TTSでは詳細なVOICEVOX用指定を同等に再現できません。

### 作品メモと初回の準備

途中の話から解析を始める場合、確認画面に対象話と、メモ作成に必要な過去の範囲を表示します。開始すると、未準備の過去本文を順番に取得し、約32,000文字までをまとめて人物・関係・重要な出来事・現在の状態へ要約します。過去全話への細かい演技付けは行いません。初回には、その話数と通信速度に応じた時間・GPT利用量がかかります。

作成したメモを保存し、次からは再利用します。新しい話の解析では演技とともにメモの変更分を受け取り、対象話が完了してから次の話に引き継ぎます。既存の詳細演技だけが保存されている場合は、演技を変えずにメモだけを準備できます。過去の本文を確認できない場合は不足範囲を表示し、取得できる対象話の解析を続けます。未取得の話を読んだことにはしません。

メモは話数に対応したスナップショットです。後の話で作成した自動メモや手動メモを、前の話の解析に渡しません。配役登録は本作品共通です。元の本文が変更された場合は影響する自動メモを無効化します。各項目は最大320文字、全体は最大120項目で、上限では古い自動生成の出来事・場面などから整理します。全情報を永久に保持する全文データベースではありません。固定した利用者のメモは自動整理の対象外です。

本棚の作品管理、または読み上げ画面の **「作品メモ」** で、対象時点・確認済み範囲・出典・未確定の項目を確認できます。項目を一つずつ編集・追加・削除できます。手動で修正・追加・削除した項目は、編集画面に表示した話以降へ適用します。その前の話には後の情報を渡しません。修正は手動固定し、GPTの変更より優先します。手動で追加したメモに架空の出典は付けません。配役の声は従来どおり **「配役・声を編集」** で管理します。

### 句ごとの演技を手動で直す

「区間を修正」→一覧から区間を選択→「細かい演技を使う」で各句を編集します。必要に応じて「速さ・高さ・抑揚・音量・間・語尾・強調」を展開し、「修正を固定して保存」を押します。上部には元の本文、各句にはルビを反映した読み上げ用文字列を表示します。

未固定の結果では「話者のAI自己評価」「感情のAI自己評価」を別表示します。手動保存後は「手動固定」の表示を優先し、GPTの解析・再確認から保護します。話者だけを変更した場合は詳細演技を保持します。「区間全体を指定」を選んで保存すると、句ごとの指定を解除して全体の値を使います。切り替えただけでは保存済み演技は変わりません。解析中の手動修正も、遅れて届いたGPT応答で上書きしません。声を変えるときは「配役・声を編集」を使います。

### 開始話・話数の指定

「聴く」→ **「まとめてGPT解析」** で開始話と話数を指定できます。**「現在の話から10話」** は表示中の話を含む10話です。例えば第25話なら第25〜34話を処理します。番号は取得した目次に基づきます。

保存済み本文を優先し、必要な本文を1話ずつ取得・解析します。精密解析は上記の一話方式、標準解析は従来の40区間・約8,000文字を目安にします。標準解析では作品メモを追加送信しません。1区間の途中を切り捨てず、章全体の区間数での打ち切りもありません。完了した結果を保存し、中断・通信失敗後は未完了部分から再開できます。読み位置・既読状態・固定配役は動かしません。

再開では、開始時に確認した精密／標準・作品メモ・解析フローを使用します。設定画面の変更は新規解析へ反映します。旧版で開始した範囲は保存された従来方式で再開し、新しい過去本文の処理は追加しません。

「保存した範囲の続きを解析」→確認→「同じ条件で解析を再開」と操作します。解析方式、GPTアカウント・モデル、ルビ設定は開始時の条件に戻す必要があります。

範囲の確認画面には実際の対象を表示します。完全な目次で末尾を超える場合は残り話数に調整し、確認後に増えた話を追加送信しません。目次が一部だけの場合は取得済みの開始話と次話リンクを確認し、飛び番・別作品・未解放章では停止します。

開始した解析は通知付きのサービスで継続し、画面を閉じても処理します。通知または解析欄から中断できます。OSがプロセスを終了した場合は保存済みの残りから手動で再開します。起動時に本文を自動送信し直す処理はありません。

解析欄の「この話の今回の解析」には開始・再開ごとの要求回数と時間を表示します。「作品メモ準備の計測」は保存した解析ジョブ内の累計です。二つは別の数値であり、複数話全体の演技解析時間とは区別します。

### 配役の固定と手動編集

本棚の作品管理、または「聴く」の「配役・声を編集」から独立したページを開けます。人物名・別名で検索し、語り手・主要人物・脇役などで絞り込めます。

名前、別名、役割、性別表現、**「この人物のキャラ音声」**、話し方、話速、声の高さ、端末TTSの音声を編集できます。人物の追加にも対応します。保存したプロフィールと声はGPTの自動判定より優先します。編集途中の下書きは実行中の画面内で保持し、保存時に確定します。

再生中に配役や区間を修正すると再生を停止し、次の再生から修正を使います。GPTは話者・感情などのメタデータを返し、小説本文をモデルの文章で置き換えません。話者判定の誤りは「区間を修正」で手動固定できます。

### ChatGPTログインの扱い

公式のSign in with ChatGPTによる個人用ローカルアプリ向け認証を使用します。認証は外部ブラウザーで行い、端末の一時的なループバック受信でアプリへ戻ります。認証情報はAndroid Keystoreの鍵で暗号化して保存し、UIや小説サイトへ返しません。

登録とモデル選択はアカウントごとに保持します。アカウント切り替え時は進行中の解析を中断し、作品の配役と読み上げ位置を残します。ログアウトしても本棚・配役・オフライン音声データは削除しません。受信形式エラー時は「エラーの詳細」→「詳細をコピー」でアプリ版・分類・段階などを確認できます。小説本文やログイン情報はコピー対象に含めません。

関連資料： [Sign in with ChatGPT](https://developers.openai.com/siwc/token-sharing-open-source)、[モデル一覧・推論](https://developers.openai.com/siwc/token-sharing-open-source/models-and-inference)、[セッションと利用量](https://developers.openai.com/siwc/token-sharing-open-source/profiles-and-sessions)。

## 読書とタイトルごとの管理

- **検索**：カクヨム・なろうを作品名・作者名・キーワードで検索します。Wuxiaworldは「公式サイトで探す」またはURL追加を使います。
- **URL追加**：作品の目次または各話のURLを入力します。Androidの共有メニューから渡すこともできます。
- **タイトル管理**：総話数、既読・未読、保存済み話数、目次、読書位置、付箋とメモを作品ごとに保持します。
- **続きから読む**：話・段落・スクロール位置を自動保存し、前回の位置から再開します。話を飛ばしただけでは前の話を一括既読にしません。
- **連続読書**：本文とルビを抽出して表示し、次話を先読みして縦につなぎます。保存済みの話はオフラインで読めます。
- **表示**：文字サイズ、行間、明朝・ゴシック、紙色・白・夜間、ルビ、前書き・後書きを調整できます。

### コントローラーと全画面表示

1.6.0の表示機能を維持しています。画面下の読み上げコントローラーは**初期状態で非表示**です。読書画面の「文字」、設定、「聴く」からオン・オフを変更できます。表示を消しても再生は続き、「聴く」やAndroidの音声通知から操作できます。

下方向へのスクロールで操作バーを隠す「下スクロールで全画面表示」は初期状態でオンです。上方向へスクロールするか本文をタップすると戻ります。長押しの本文選択、位置復元、音声への追従は通常のスクロール操作と区別します。全画面中の戻る操作は最初にバーを表示し、次の操作で画面を戻ります。表示設定は保存し、一時的な全画面状態は起動時に解除します。

### 読み上げの操作

再生・一時停止・停止、前後の区間、指定区間、0.5〜2倍速、スリープタイマー、次話の連続再生に対応します。音声の再開位置は読書位置とは別に保存します。通知とMediaSessionから操作し、別アプリ表示中もサービスで再生を続ける実装です。イヤホン切断時は一時停止します。

端末TTSとプロセス終了後の再開は区間先頭からです。同じプロセス内のVOICEVOX音声は音声内の途中から再開します。未保存本文の取得に失敗した場合や、章が未公開・未解放の場合は停止します。

VOICEVOX音声が未生成なら、最初の合成部分が完成した時点から再生し、残りを生成します。演技指定と音声の内容は保持します。完成した音声は検証してキャッシュへ保存し、次回はキャッシュから再生します。生成途中のシークは生成済みの範囲内です。

先読みは最大3区間・合計約15秒を目標にします。CPUでの音声生成は直列で、同時に多数のモデルを動かしません。停止・区間移動・配役変更では不要な先読みを取り消します。先読み中の区間に進んだ場合は生成中の音声を引き継ぎます。一時停止では現在の音声を保持し、先の生成を止めます。実際に途切れず再生できるかは端末の生成速度によります。合成グループが一つだけの短い区間では、そのグループの生成完了待ちは残ります。

「最初の音声準備」は最初のPCMが完成するまでの計測値です。Androidのスピーカーから音が出た時刻ではありません。Linuxの実JNI試験では、自作の約5.19秒の音声の最初の部分が294〜325 msで完成し、全体完成は1,973〜2,207 msでした。Androidの実測値とは区別します。通常の読書画面へこの計測欄を常時表示することはありません。

## 保存・TXT入出力

作品管理から **「全話を端末に保存」** を開始し、「保存」で作品ごとの進捗を確認します。全話保存が完了したら **「全編をTXTで書き出す」** でAndroidのファイル保存画面から保存先を指定します。UTF-8のTXTへ作品名、作者、出典URL、章・各話タイトル、本文、取得した前書き・後書きを出力します。

本文の全話保存はアプリを前面に開いている間に進み、別アプリへ移ると一時停止します。再開時は未保存分から続けます。目次が未確認、または未保存の話がある場合は全編TXTの完了扱いにしません。連載の追加話は作品情報を更新してから保存できます。

「TXTファイルから読み込む」で端末のTXTをオフライン作品として追加できます。UTF-8、UTF-16（BOMあり）、Windows-31Jに対応し、上限は25 MB・10万行です。長いファイルは章や区間に分けます。

### Wuxiaworldとサイトへのログイン

Wuxiaworldの作品・章URLを追加できます。例：<https://www.wuxiaworld.com/novel/warlock-of-the-magus-world>。本文は原文のまま表示します。ログインや章の解放が必要な場合は公式画面で操作し、全文が表示されたページの **「このページを『つづき』で読む」** から取り込めます。

目次が一部だけの場合は読めた章と前後リンクを確認しながら増やします。保存済みの離れた章を次話と誤認せず、先頭からの章番号・件数・総数がそろったときに全編TXTを有効にします。**「保存済みの話だけTXT出力」** なら取得済み部分を出力でき、ファイル名と冒頭に部分出力と記載します。未解放本文やアクセス制限を回避して取得する機能はありません。

小説サイトへのログインは公式ページをWebViewで開き、Cookieを本文取得と共有します。外部アカウント認証は認証元のWebView方針によって利用できない場合があります。各サイトの構造変更では抽出処理の更新が必要です。取得・保存には対象サイトの利用条件が適用されます。関連案内：[なろうのアプリ・Webサイト](https://syosetu.com/helpcenter/helppage/helppageid/183)、[なろうAPI](https://dev.syosetu.com/man/api/)。

## ソースとビルド

ソースにはAndroidのJavaコードとHTML/CSS/JavaScript UIに加え、公式VOICEVOX Java API、必要なJAR、arm64-v8a・x86_64のJNIライブラリを同梱しています。音声モデルと辞書は初回利用時に取得します。広告SDK・解析SDKは使用していません。

主な構成：

- `ReaderStore.java` / `MainActivity.java`：本棚、読書位置、目次、付箋、検索、TXT入出力。
- `SpeechPlan.java` / `SpeechAnalyzer.java` / `SpeechPerformance.java` / `CastRegistry.java`：区間化、一話のGPT解析、演技指定の展開、原文対応の検証、固定配役と移行。
- `SpeechPronunciation.java` / `SpeechReadingInput.java`：原文と読みの対応、ルビ保護、読みの検証と音声入力。
- `StoryMemory.java` / `SpeechStore.java`：出典付きの作品メモ、過去時点のスナップショット、手動固定、本文変更時の失効。
- `SpeechStore.java` / `SpeechController.java` / `SpeechAnalysis*.java`：読み上げ設定、保存位置、範囲解析と通知。
- `ChatGpt*.java`：ブラウザーログイン、アカウント保存、モデル一覧、応答の受信・検証。
- `OfflineVoices.java` / `VoicevoxEngine.java`：10声の対応スタイル、抑揚の反映、VOICEVOXによる合成。
- `OfflineVoicePacks.java` / `OfflineVoiceDownloadService.java`：音声モデル・辞書の取得、確認、中断・再開。
- `SpeechAudio.java` / `SpeechPcmSource.java` / `PcmPlayback.java` / `AndroidPcmOutput.java` / `SpeechService.java`：部分生成からの再生、キャッシュ、先読み、通知・MediaSession。
- `app/src/main/assets/app.js` / `app.css` / `extractor.js`：画面と小説サイトの抽出処理。
- `app/src/main/assets/voice-licenses.txt`：アプリ内で表示する音声・辞書・依存ライブラリの利用条件。

ビルド手順は [scripts/BUILD.md](../scripts/BUILD.md)。Java依存関係は `third_party/offline/dependencies.json`、公式VOICEVOX JAR/AARとJNIの固定情報は `third_party/offline/native-dependencies.json` に記録しています。配布ソースZIPに署名鍵は含めません。
